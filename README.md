# FastAPI 会话认证与授权

基于 FastAPI 的本地可运行会话认证 / 授权 / 防护演示。内存实现、线程安全，
所有失败结论在各入口下统一为 `{reason, detail}` 结构，可区分、可解释。

## 本地运行

```bash
uv sync
uv run fastapi dev main.py        # 或 uv run uvicorn main:app --reload
```

种子账号：`admin/admin-pass`（admin）、`alice/alice-pass`、`bob/bob-pass`（user）。

  旧标识按 `session_revoked` 拒绝；
- 同一来源 20 个不同账号并发正确登录全部成功且会话独立、同账号 8 端并发

  跨客户端验证防护状态为服务级共享。

手工验证示例：

```bash
# 登录（响应设置 session Cookie，并返回 csrf_token）
curl -i -c jar.txt -X POST localhost:8000/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"alice-pass"}'

# 受保护读取
curl -b jar.txt localhost:8000/auth/me

# 状态变更需携带 X-CSRF-Token（取登录响应中的 csrf_token）
curl -b jar.txt -X POST localhost:8000/auth/logout -H "X-CSRF-Token: <token>"
```

新增端点示例：

```bash
# 查看本人当前所有有效会话（多端）
curl -b jar.txt localhost:8000/auth/sessions

# 只撤销其中一条（session_id 取自列表返回值，需 CSRF）
curl -b jar.txt -X POST localhost:8000/auth/sessions/revoke \
  -H 'Content-Type: application/json' -H "X-CSRF-Token: <token>" \
  -d '{"session_id":"<目标会话完整标识>"}'
```

## 会话与令牌生命周期

1. **签发**：`POST /auth/login` 校验凭证后签发全新随机会话标识
   （HttpOnly Cookie）与独立的 CSRF 令牌（响应体返回）。
   每次登录都是全新标识，避免会话固定。
2. **使用与续期**：受保护请求凭 `session` Cookie 解析会话。会话有两个
   时间维度：
   - **空闲有效期（默认 1800s）**：每次受保护访问都会在锁内原子地向后
     滑动（滑动续期），持续活动不会被踢；长时间不活动则按原方式自然到期
     （`401 session_expired`）。同一会话的并发访问共享同一状态，
     “校验 + 滑动”在同一把锁内完成，不会把到期时间算错或弄丢会话。
   - **绝对上限（默认 14400s，自本次登录算起）**：续期只能滑动空闲截止，
     永远不能越过绝对截止；即便一直活动，到绝对上限仍会自然到期。
     权限变化引发的会话标识轮换属于同一条登录沿袭链，**不重置**登录时间
     与绝对上限。
3. **多端会话管理**：同一账号可在手机、平板、电脑等多端同时登录，
   每端一条独立会话。
   - `GET /auth/sessions`：只列出**本人名下**当前有效会话，每条含
     登录时间（`created_at`）、最近活动时间（`last_seen_at`）、空闲/绝对
     到期时间，以及该会话**当前**看到的角色（按用户实时记录，权限调整后
     立即体现，无需等待或重登）。
   - `POST /auth/sessions/revoke`（需 CSRF）：只撤销本人名下指定的一条
     会话（按 `session_id`，取自列表返回值），其余会话完全不受影响、
     照常可用。被撤销的标识此后任何请求一律返回
     `401 session_revoked`，与自然过期（`session_expired`）明确区分；
     撤销他人或不存在的标识统一返回 404，不透露标识归属。
4. **轮换与“被拒不毁会话”**：用户角色/权限变化（`role_version` 自增）后，
   该用户下一次认证请求会**原子轮换**会话标识：旧标识立即立墓碑失效，
   新标识通过 `Set-Cookie` 下发，新 CSRF 令牌通过 `X-CSRF-Token` 响应头
   下发（即使该请求随后因越权返回 403，错误响应也会补发新标识与新令牌）。
   因此权限（尤其被降权）调整后：带着该会话做没有权限的操作会被
   `403 forbidden` 拒绝且不泄露任何资源内容；但这次拒绝**不会**使会话失效——
   随后查看本人信息、查看会话列表、正常登出都不需要重新登录。
   轮换当次请求允许沿用上一代 CSRF 令牌一次，之后重放上一代令牌返回
   `403 csrf_invalid`。
5. **撤销**：`POST /auth/logout` 撤销当前会话；管理员可
   `POST /admin/revoke` 撤销某用户全部会话。已撤销/已轮换的标识复用
   一律返回 `401 session_revoked`，不会被再接受。
6. **CSRF 令牌**：与所属会话绑定、不跨会话复用。状态变更请求
   （logout / 会话单条撤销 / admin 写操作）必须携带 `X-CSRF-Token`：
   缺失 `403 csrf_missing`；无效 `403 csrf_invalid`；
   属于其他会话 `403 csrf_cross_session`。

## 权限判定顺序

每个受保护请求按以下顺序判定，任一环节失败即拒绝并给出可区分原因：

1. **会话解析**：无标识/未知标识 `401 unauthenticated`；
   已撤销或已轮换 `401 session_revoked`；
   空闲截止或绝对截止到达 `401 session_expired`。
2. **滑动续期**：原子完成空闲截止的滑动（不越过绝对上限），无论随后
   授权是否通过；并发访问不会算错到期时间或弄丢状态。
3. **权限变化轮换**：会话的 `role_version` 落后于用户当前值时原子轮换，
   新标识随错误响应也会下发（被拒不等于会话失效）。
4. **CSRF 校验**（仅状态变更端点）：见上。
5. **角色判定**：默认拒绝。角色按请求时刻的用户记录实时判定
   （不缓存授权结果），角色变更后既有会话立即按新权限判定：
   未认证 `401 unauthenticated`，已认证但角色不足 `403 forbidden`。
   越权响应不携带任何资源内容，不暴露受保护资源是否存在。

## 暴力破解防护与锁定策略

- **双维度计数**：按账号与来源（客户端 IP）分别累计失败次数，
  任一维度达到阈值（默认 5 次）即进入锁定期（默认 60s）。
- **确认失败才计数 + 维度级并发名额**：失败次数只在口令被确认错误后
  计入；同时用条件变量把同一维度上“进行中的登录尝试 + 窗口内已确认
  失败”的总数限制在阈值以内。因此**多设备拿各自账号的正确口令并发登录
  （如批量上线自检）只会排队拿名额、全部成功、各自拿到独立会话，不会被
  误伤**；只有口令确实错了、连续累计到阈值的才被拦下。并发错误尝试同样
  不丢计数、不超额放行。
- **服务级共享状态**：阈值与锁定状态集中在应用内同一个 `RateLimiter`
  实例（一把锁/条件变量保护），所有请求共享，不会因每个请求各持一份
  状态而被绕过。
- **可区分原因**：账号锁定 `429 account_locked`，
  来源锁定 `429 source_locked`，凭证错误 `401 invalid_credentials`。
- **自动恢复**：锁定期满后计数与锁定状态自动清除，
  正常请求即可通过，不会被长期拒绝。

## 目录结构

```
app/
  errors.py     # 失败原因码与领域异常（结论结构与判定顺序保持不变）
  models.py     # User / Session / Role（空闲+绝对双截止、最近活动时间）
  security.py   # PBKDF2 口令散列、随机令牌
  store.py      # 线程安全用户/会话存储（墓碑、轮换、续期、多端列表/单撤）
  ratelimit.py  # 维度级并发名额 + 确认失败才计数、双维度锁定
  service.py    # 登录/登出/续期/会话列表/单撤/轮换/CSRF 判定
  deps.py       # FastAPI 依赖：认证→续期→轮换→CSRF→角色
main.py         # 路由装配与统一错误处理（错误响应补发轮换 Cookie）
tests/
  test_auth.py              # 原有能力回归基线（14 个）
  test_session_management.py # 本轮新增行为（11 个）
```
